# ボリュームチェックから総合図へ — 全体設計のための背景資料

2026-09-15 時点。claude.ai プロジェクトのナレッジとして使うことを想定した、コードに依存しないまとめ。

---

## 1. 目的

オフィス・テナントビルの企画段階で、**敷地を指定するだけで法規条件を取得し、建てられるボリュームと複数案を自動生成し、そこから基本設計の図面セット（総合図への受け渡し）まで機能として積み上げる**。

使う人は設計者。ツールは「設計者が決める前に、決めるための数字と図を全部そろえる」ところまでを担い、意匠・行政協議・地盤など判断が要る部分は担わない。**企画検討用の試算であり、確認申請には使わない**。

## 2. いま出来ていること

Web 画面（地図で敷地を指定）と DXF 出力がある。

**法規の算定**
- 容積率（前面道路幅員による低減 法52条2項）
- 建蔽率と緩和（防火地域の耐火建築物・角地・指定80%→制限なし 法53条）
- 道路斜線（適用距離の頭打ちを含む 法56条1項1号・別表第三）
- 隣地斜線（法56条1項2号）
- 北側斜線（法56条1項3号。真北方向に測る。中高層住専は日影規制の指定で外れる）
- 絶対高さ制限（法55条）
- 天空率による道路斜線・隣地斜線の緩和可能性（法56条7項・令135条の5〜10）

**敷地と建物**
- 任意形状の敷地（地図で角をなぞる）、辺ごとの道路幅員、2面道路
- 建物の振り角（道路平行が0）
- 外壁後退。斜線と足さず大きいほうを適用

**検討支援**
- 各階の形状・面積表・打ち切り理由（容積率／最小成立面積／絶対高さ／範囲なし）
- どの規定がどれだけ削っているか（「この規定を外せば +○㎡」）
- 複数案の自動生成（向き・階高・外壁後退・耐火を総当たり、延床順）。天空率で開けるかの列を付けられる
- 天空率が通らないとき、外壁後退を広げて通る案を提示
- 用途地域・建蔽率・容積率・防火地域の自動取得（不動産情報ライブラリ API。高度地区・道路種別・日影規制の指定は公開データにないので手入力）

**出力**
- 断面図・配置図・各階平面図（画面）
- DXF 1枚（配置図＋断面図＋面積表＋表題欄。適用した規定と根拠条文、未考慮事項を印字）

## 3. 設計思想（これまで守ってきたこと）

1. **法規の数値は1か所に集約し、条文番号を添える。** 推測で値を置かない。読み切れないときは厳しい側を既定にして理由を残す。
2. **手計算で検算できる形に作る。** 期待値を先に書き、実装をそれに合わせる。
3. **土台を替えるときは従来結果との一致を数値で示す。**
4. **未考慮の事項はすべて出力に印字する。** 使う人が「何を見ていないか」を常に読める。
5. **安全側に倒す。** 緩和は根拠が確かなものだけ適用する。
6. **人が決めることと機械が出すことを分ける。** 法規条件は敷地で決まる（振らない・聞く）、計画条件は設計者の選択（既定値で進めて明示する）。

## 4. 決めてきたこと（要点と理由）

- **外壁後退と斜線後退は max。** どちらも「境界線からの離れ」なので、大きいほうだけが効く。当初の足し算から変更し、各階が広くなった。
- **天空率の計画建築物は「全階同一平面の箱」。** 上階の後退をなくすのが天空率の狙いだから。階数は容積率を使い切る最小。
- **適合建築物は境界線ごとに作り（敷地区分方式）、高さは計画建築物の最高高さで頭打ち。** 隣地について頭打ちの要否は条文から一義に読めなかったので厳しい側を既定にした。頭打ちなしなら余裕は必ず広がる＝「通る」と出れば読み方によらず通る。
- **算定位置は「斜線面がどこから見ても仰角一定に見える線」の上。** 道路は反対側の境界線、隣地は境界から立ち上がり÷勾配（16m／12.4m）外側。
- **北側斜線は辺ごとの帯では表せない。** 真北方向に敷地を収縮させる形で解く。
- **複数案は「斜線を守った延床」順。** 天空率で開ける案（外壁後退が大きい）は下に来るので、後退ごとの最良案を末尾に足している。
- **建物は板を絞らず、収まらない階を切り捨てる。** そのため防火地域で耐火にすると建築面積は増えるのに延床が減ることがある。これは既知の挙動で、事業性を見るなら板を絞る方式（天空率側で実装済み）に寄せるべきか、全体設計で決めたい論点。

## 5. 未対応・限界

| 項目 | 状態 |
|---|---|
| **日影規制**（法56条の2・別表第四） | 未実装。住居系で致命的。日影規制の指定を立てると北側斜線が外れるだけで**安全側にならない** |
| 北側斜線の天空率 | 未対応 |
| 法56条4項 後退距離の緩和／令132条 2以上の前面道路／法52条9項 特定道路 | 未考慮（実際より小さく出る） |
| 容積率不算入（EV・共用部・駐車場） | 未考慮（床面積＝容積対象。実際より厳しい） |
| 屋上部分の高さ算入除外（令2条1項6号ロ） | 未考慮 |
| 高低差のある敷地 | 平坦前提 |
| 高度地区・地区計画 | 手入力 |
| 天空率の市販ソフト（ADS 等）との照合 | 未実施。定義に対する独立検証のみ |
| **コア比率** | 入力の仮定（既定18%）。貸室面積＝事業性の根っこがここに依存している |

## 6. これからの道筋（合意済み）

「箱」に骨格を入れ、事業性で案を選び、図面セットへ。

**第1段：箱に骨格を入れる**
1. **コア計画** — コア位置候補（センター／サイド／2コア）、EV台数（交通計算の簡易版）、階段2か所（令121条）、31m超の非常用EV（法34条2項）→ 根拠のある有効率と基準階平面図。**ここから着手**
2. 避難・防火チェック — 歩行距離（令120条）、面積区画（令112条）、非常用進入口（令126条の6）を警告として
3. 構造グリッド — スパン割、必要階高の逆算（天井高＋梁＋OA床＋設備）

**第2段：事業性で選ぶ**
4. 駐車・駐輪・荷さばき（自治体条例は入力）→ 面積と容積不算入
5. 事業収支 — 概算工事費・賃料・NOI・利回り。複数案の並びを延床順から利回り順へ

**第3段：図面セット**
6. 配置図・各階平面図（コア・柱・外壁）・断面図・立面図・面積表の DXF セット
7. 総合図への受け渡し — 通り芯・階レベル・コア・PS/EPS を構造・設備が引き取れる形（レイヤ規約、将来 IFC）

**並行**：日影規制（第1段と同時期）

**対話式**：設計者が自然言語で条件を伝える形は、MCP サーバー → Web のチャット欄の順で。LLM は翻訳と説明だけを担い、数値はすべて算定側から。「コアを東に寄せて」と言える単位で機能を切る。敷地の形は人が地図で描く（LLM は地図を見られない）。

## 7. 全体設計で決めたい論点

- **データモデル**：ボリューム結果 → 基準階（コア・柱）→ 図面セット、と段が進むときの「案」の持ち方。1案＝何を含む1オブジェクトか。上流を変えたとき下流をどう無効化・再計算するか
- **案の識別と履歴**：複数案の比較・対話での修正を重ねたとき、どの案がどの条件だったかを追える形
- **板を絞るか階を切り捨てるか**：容積率を使い切る方針（§4 最後）
- **法規の適用単位**：敷地区分方式で進めているが、一の隣地方式が要る場面はあるか
- **自治体ごとの値**（駐車場条例・日影の種別・高度地区）の入力の粒度と、取得できない事実の明示の仕方
- **構造・設備への受け渡し形式**：DXF のレイヤ規約で足りるか、IFC をいつ入れるか
- **対話の状態管理**：会話の状態＝いまの入力条件、とするときの差分の扱いと「法規は変えさせない」の担保
- **検証の方法**：手計算で検算できる範囲を超える機能（日影・コア計画）をどう担保するか

## 8. 用語と単位

- 建蔽率・容積率は倍率表記（0.8＝80%、6.0＝600%）
- 有効率（レンタブル比）＝貸室面積÷延床面積。現在は「1−コア比率」の仮定
- 適合建築物＝斜線制限どおりに敷地いっぱいに建てた立体（天空率の比較相手）
- 計画建築物＝斜線を天空率で外して建てたい形
- 算定位置＝天空率を測る点（令135条の9・10）
- 内部の長さは mm、面積は mm²。表示は m・m²

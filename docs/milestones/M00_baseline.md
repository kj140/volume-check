# M00 現状の固定

## 目的

土台を作り替える前に、今のコードが何をどう出しているかを記録し、結果を回帰テストとして固定する。以後のマイルストーンで「従来結果と数値で一致する」ことを示すための基準にする。

## 前提

- 読む文書：`CLAUDE.md`、`docs/architecture.md`、`docs/project_brief.md`
- **本体コードには手を入れない。** 追加してよいのは `docs/` と `tests/` 配下のファイルと、テストの実行に必要な最小限の設定だけ。

## 作業

1. **Git の状態を確認する。** リポジトリでなければ初期化し、現状を最初のコミットにする。
2. **リポジトリ全体を読み、`docs/current_state.md` を書く。** 次の項目を含める。
   - 言語・主要ライブラリとその版、起動方法、既存テストの有無と実行結果
   - Web 画面の技術構成と、画面から算定までの呼び出しの流れ
   - 入力の形（項目の一覧、既定値とその定義場所）
   - 出力の形（算定結果の構造、DXF のレイヤ名・図の構成）
   - 法規定数の場所、条文番号が付いていない定数の一覧
   - 座標系・単位・真北の扱い
   - 外部 API（不動産情報ライブラリなど）を呼んでいる箇所。solver の内部から呼んでいるかどうか
   - 決定的でない箇所（乱数、時刻、並び順が定まらない処理）
   - `docs/architecture.md` のフォルダ構成との対応表（現在の場所 → 目標の場所）
   - `docs/architecture.md` と食い違う点、気づいた懸念（**修正はしない。記録だけ**）
3. **回帰ケースを用意する。** 既存のテストや例の入力を優先して使い、足りない分を作る。最低限、次の性質を1つ以上含むケースをそろえる（1ケースで複数を兼ねてよい）。
   - 矩形敷地・1面道路
   - 2面道路（角地）
   - 任意形状の多角形敷地
   - 建物の振り角が0でない
   - 北側斜線がかかる用途地域
   - 絶対高さ制限で打ち切られる
   - 容積率で打ち切られる
   - 外壁後退が斜線による後退より大きい
   - 防火地域で耐火の有無を切り替える
   - 天空率で道路斜線または隣地斜線が外れる判定になる
   - 複数案の自動生成
   - 天空率が通らず、外壁後退を広げた案が提示される
4. **結果を固定する。** 各ケースについて、`tests/regression/<ケース名>/` に次を保存する。
   - `input.json`：入力
   - `result.json`：算定結果の全体（各階の形状と面積、打ち切り理由、規定ごとの削減量、案の一覧と並び順、天空率の判定、適用規定・未考慮事項の出力）
   - `dxf_summary.json`：DXF から取り出した内容（レイヤごとの図形数、文字の内容を並べ替えたもの、線の端点を小数3桁に丸めたもの）。DXF ファイルのバイト比較はしない
5. **外部 API をテストから切り離す。** 回帰ケースで使う API 応答を `tests/fixtures/` に記録し、テストはネットワークなしで動くようにする。
6. **回帰テストを書く。** 現在のコードで各ケースを実行し、保存した結果と比較する。浮動小数は相対誤差 1e-9 以内で一致とする。
7. **`CLAUDE.md` の「コマンド」欄を埋める。**
8. **完了時のコミットに `m00-baseline` のタグを付ける。**

## 受け入れ条件

- [ ] `docs/current_state.md` が作業2の項目をすべて含む
- [ ] 回帰ケースが作業3の性質をすべて含む（どのケースがどの性質を含むかの対応表を `tests/regression/README.md` に書く）
- [ ] 回帰テストが、変更していない現在のコードで全件通る
- [ ] 回帰テストを2回続けて実行し、2回とも同じ結果になる
- [ ] ネットワークを切った状態で回帰テストが通る
- [ ] `docs/`・`tests/`・テスト設定以外のファイルに差分がない（`git diff --stat` で示す）
- [ ] `CLAUDE.md` の「コマンド」欄が埋まっている

## やらないこと

- バグの修正（見つけたら `current_state.md` に記録するだけ）
- リファクタリング、ファイルの移動、依存ライブラリの追加・更新（テスト実行に必須のものを除く。追加したら報告する）
- フォーマッタの適用
- 回帰ケースの結果が「正しいか」の判断。M00 は現状を固定するだけで、正しさは手計算ケースで別に確かめる

## 着手前に確認すること

- 既存の手計算ケース（検算済みの例）があれば、その場所をユーザーに聞く。あれば `tests/cases/` に移し、回帰ケースにも含める
- 決定的でない処理が見つかり、固定のためにコード変更が必要になりそうなら、変更せずに止めて相談する

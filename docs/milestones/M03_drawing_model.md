# M03 共通の図面モデルに移し、DXF と PDF を出す

## 目的

図面を「段の結果 → 図面モデル → 出力器（DXF・PDF）」の流れに移す。DXF と PDF が同じ図面モデルから出るので、両者の内容がずれない。
あわせて、段の結果にある「適用規定・未考慮事項・既定値で進めた条件」を、そのまま図面に印字できるようにする（決定 0006 の高度地区・地区計画の未確認が、ここで初めて図面に載る）。
総合図の段（M10 以降）の図面も、この図面モデルの上に作る。

## 前提

- M02 が完了している（`run_volume_stage`、`StageResult`、案の API）。決定 0006 の修正も済んでいる（タグ `m02-notes`）。
- 読む文書：`CLAUDE.md`、`docs/architecture.md` 7章、`docs/current_state.md` 4章（DXF の構成）・11章（レイヤ接頭辞の食い違い、注記文言の懸念）、`docs/decisions/0005`・`0006`。

## 作業

1. **図面モデルを定義する（`drawing/model/`）。** 単位は mm。
   - `Sheet`（用紙・図枠・ビューの並び・注記ブロック）、`View`（名前・縮尺・原点・図形の並び）
   - 図形：線、折れ線（閉じる／閉じない）、円、文字（高さ・寄せ・回転）、寸法（2点間）
   - すべての図形はレイヤ名と線種を持つ。色・線幅はレイヤ規約から決まる（図形に直接持たせない）。
   - `NoteBlock`：企画検討用・確認申請に使えない旨、適用規定と条文、未考慮事項（向き＝`direction` つき）、既定値で進めた条件。
2. **レイヤ規約を1か所にまとめる（`drawing/layers.py`）。** 既存の7レイヤを移す。`S-SITE`・`S-ROAD` の扱いは「着手前に確認すること」の決定に従う。`S-`・`M-`・`E-` の枠を予約する。
3. **段の結果から図面モデルを組み立てる（`drawing/build/volume_sheet.py`）。** 入力は `StageResult`（volume）と `Scheme`。
   - 配置図・断面図・面積表・表題欄・注記を、既存の `drawer.py` と同じ配置で組み立てる。形の計算は既存の `section.py`・`plan.py` を使い、**新しく計算しない**。
   - 注記ブロックは `StageResult` の `applied_rules`・`not_considered`・`defaults_used`・`warnings` から作る。`direction="larger_than_actual"` の未考慮事項は、注記ブロックの先頭に目立つ形（枠・記号）で出す。
4. **DXF の出力器（`drawing/export/dxf.py`）。** 図面モデル → DXF。図面範囲と初期ビューの設定（現行 `drawer._fit_initial_view`）を引き継ぐ。
5. **PDF の出力器（`drawing/export/pdf.py`）。** 図面モデル → PDF（A3 横）。日本語が文字化けしないこと。使うライブラリとフォントは「着手前に確認すること」の決定に従う。
6. **出力器の関所。** 注記ブロックがない、または必須の項目（企画検討用の旨・適用規定・未考慮事項・既定値）が欠けている図面モデルを、DXF・PDF どちらの出力器も受け付けない（例外）。
7. **API を足す。** `GET /api/schemes/{id}/drawings/volume.dxf`、`.../volume.pdf`（volume の段の結果がなければ実行してから出す）。M02 と同じく localhost 専用の `api/` に置く。
8. **既存の `drawer.py` と公開中の画面は残す。** 画面の「DXF をダウンロード」を新しい流れに切り替えるかは、M03 の完了報告を見て決める（別のマイルストーン）。
9. `docs/current_state.md` と `tests/regression/README.md` を更新し、決めたことを `docs/decisions/` に記録する。

## 受け入れ条件

- [ ] 全回帰ケースで、新しい流れの DXF の**図形**（線・折れ線・円・寸法の座標、レイヤごとの数）が、既存の `drawer.py` の DXF と一致する。一致しないものは、注記ブロックの行数の違いによる平行移動だけであることを、M02 後の注記修正と同じ方法（平行移動を引いて比較）で示す
- [ ] 全回帰ケースで、新しい流れの DXF の**文字**が、既存の DXF の文字を過不足なく含む。増えた文字は、段の結果にしかない項目（高度地区・地区計画の未確認、既定値で進めた敷地事実）だけであることを一覧で示す
- [ ] 全回帰ケースで PDF が出力され、ページが A3 横で、注記ブロックの文字（日本語）が PDF から文字として取り出せる
- [ ] DXF と PDF で、同じ図面モデルから出た文字の集合が一致する
- [ ] 注記ブロックがない／必須項目が欠けた図面モデルを、DXF・PDF どちらの出力器も拒否する（項目ごとにテスト）
- [ ] `larger_than_actual` の未考慮事項が、注記ブロックの先頭に出る
- [ ] レイヤ名はすべて `drawing/layers.py` から来る（出力器・組み立てに文字列でレイヤ名を書いていないことを検査する）
- [ ] `drawing/` が `solver/`・`api/`・`store/` を import しない（段の結果を読むだけ）。依存の向きのテストに追加する
- [ ] API（テストクライアント）で、案の作成 → DXF・PDF の取得が通る
- [ ] 回帰テスト・既存の DXF テスト（`tests/test_dxf_smoke.py`）が全件通る。**算定の数値は変わらない**

## やらないこと

- 算定の変更
- 公開中の画面・`web/app.py` の `/api/dxf` の切り替え（M03 の後に判断）
- 画面の SVG（`web/svg_*.py`）の図面モデルへの移行（必要になったら別のマイルストーン）
- 客先向けシート（M08）、IFC、総合図の図面（M10 以降）
- 図面の見た目の作り直し（配置・文字の大きさは既存のまま）

## 着手前に確認すること

1. **PDF を作るライブラリ（依存ライブラリの追加になる）。** 候補：
   - A. `reportlab`：PDF 専用。文字が文字として埋め込まれ、検索・コピーできる。フォントを自分で登録する。**推奨**
   - B. `matplotlib`：すでに開発用に入っている。図の描画は得意だが、文字の配置の細かい制御と、文字を文字として残す設定に手間がかかる
   - C. ezdxf の描画機能＋matplotlib で DXF を絵にする：DXF からの変換になり、「一方から他方へ変換しない」（architecture 7章）に反する
2. **日本語フォント。** 公開用の Docker イメージ（python:3.13-slim）には日本語フォントが入っていない。候補：
   - A. IPAex ゴシックなど**再配布できる**フリーフォントをイメージに入れる（**推奨**。ライセンス表記を README に書く）
   - B. PDF はローカルでだけ出す（Windows の MS ゴシックを使う）。本番では PDF を出さない
3. **既存のレイヤ `S-SITE`（敷地境界）・`S-ROAD`（道路）の名前。** 規約では `S-` は構造用に予約している。候補：
   - A. `A-SITE`・`A-ROAD` に改める（**推奨**。総合図で構造のレイヤと混ざらない）。DXF を受け取る人にとってはレイヤ名が変わる
   - B. 敷地・道路は `C-`（土木・外構）などの別の接頭辞にする
   - C. 今のまま（規約に例外を書く）
4. **図面に印字する注意書きの文言。** いまの文言（`drawer.DISCLAIMER`）は「矩形敷地のみ対応」「天空率…未考慮」と書かれていて、現状（任意形状・天空率・北側斜線に対応）と合わない。新しい流れでは、固定の文言を「企画検討用・確認申請に使えない・建築士の確認が必要」だけにし、未考慮の項目は段の結果から自動で並べる形にしたい（**推奨**）。既存の `drawer.py` の文言も合わせて直すか（直すと回帰結果の文字が変わる）

# 0003 M01 データモデルの決め事

**状態：** 決定
**日付：** 2026-09-17
**決めた人：** ユーザー（座標系・事実／条件の分類・既定値）、Claude Code（実装上の選択。ユーザー確認済みの方針の範囲内）

## 背景

M01 で案（Scheme）・敷地事実（SiteFacts）・計画条件（PlanConditions）の型を定め、保存できるようにした。
その際に決めた点を記録する。

## 決定

| 論点 | 決定 | 検討した選択肢 | 理由 |
|---|---|---|---|
| 座標系 | **既存の座標系を正**とし、`architecture.md` §4.1 を書き直した | §4.1 の案（X＝東・Y＝北・原点＝第1頂点・真北は時計回り正）に寄せる | 算定結果が一切変わらず、既存入力との相互変換が単純。§4.1 自身が「既存を記録してそれを正とする」としていた |
| 敷地事実と計画条件の分け方 | 敷地事実＝形・道路幅員・`road_side`・`north_angle`・`corner_lot`・用途地域・建蔽率・容積率・絶対高さ制限・防火地域・日影規制の指定。計画条件＝階高（基準階・1階）・外壁後退・コア比率・最大階数・耐火・振り角 | `max_floors` を探索条件として別枠にする | 法規条件は敷地の事実、設計者が動かすものは計画条件（architecture §4.3/4.4）。`max_floors` は設計者が決める値なので計画条件 |
| 計画条件の既定値 | 4.2m／4.5m／0.5m／18%／30階／耐火でない／道路に平行（`origin="default"`） | 既定値を置かず必須にする | 既に画面（index.html）と `/healthz` が使っている値で、新しく決めた数字ではない |
| 型の定義 | pydantic v2（2.13.5、fastapi 経由で導入済み）。`requirements.txt` に明示した | 既存 `models.py` と同じ dataclass | M01 の指示どおり。既存の Web 層が pydantic を使っており、API（M02）とそのまま接続できる |
| `input_hash` の対象 | 敷地事実と計画条件の**値**だけ。出所（source／source_name／retrieved_at／note／origin）は含めない | 出所も含める | 同じ値なら誰がいつ入れても算定は同じ。出所を含めると取得時刻の違いだけで再計算が走る |
| `site_id` | 根の案は自分の `id`。子案は親から引き継ぐ | 敷地事実のハッシュから作る | 画面から敷地事実を直したときも同じ敷地の履歴に残る。ハッシュ由来だと訂正のたびに敷地が分かれる |
| 既存入力で省略された敷地事実 | `source="unavailable"`（値なし）。既存入力へ戻すときは省略し、既存コードの既定（指定なし・角地でない・日影規制なし・真北は `road_side` から）が効く | 既存コードの既定値を `manual` として埋める | 「取得できない事実は unavailable、推測値で埋めない」（architecture §4.2）。既存の挙動も変えない |
| 既存入力で明示された敷地事実 | `source="manual"`、`source_name="既存入力 JSON"` | `drawn` | 既存 JSON からは地図でなぞったか手入力かを区別できない |
| 矩形入力の保持 | `SiteFacts.shape_form`（rectangle／polygon）を持ち、矩形は同じ形で戻す | 多角形に統一する | 既存の回帰入力と同じ形に戻せることを受け入れ条件にしているため |
| 既存入力への往復の「一致」 | 算定側の入口（`VolumeInput.from_dict`）を通した結果と `solve()` の結果が等しいこと。省略されたキーと既定値と同じ明示値は区別しない | 辞書の完全一致 | `fire_zone: "指定なし"` を書いた入力と書かない入力は同じ意味であり、区別する価値がない |
| 差分の形（敷地事実） | `{"path": "site_facts.fire_zone", "value": {"value": ..., "source": ..., "source_name": ...}}`。`{"source": "unavailable"}` で不明に戻せる | 値だけ渡して出所は別引数 | 出所の必須化を型で表せる |
| 用途地域名などの検査 | `model/` では文字列のまま。算定側（`constants.py`）が検査する | `model/` に名前の一覧を持つ | `model/` が既存コード（将来の `solver/law/`）を import しない向きを守るため。名前の一覧を二重に持たない |
| `store/` の重複保存 | 同じ id・同じ内容の `save_scheme` は何もしない。内容が違えば拒否 | 常に拒否 | 再実行に強くしつつ「案は書き換えない」を守る |
| 段の結果の重複保存 | 同じ (案, 段, input_hash, solver_version) は置き換える | 拒否 | 再計算の結果で上書きしてよい（同じ入力・同じ版なら同じ結果のはず） |

## 影響

- 算定結果には影響しない（solver は無変更、回帰テスト全件通過）。
- `requirements.txt` に `pydantic==2.13.5` を追加（既に fastapi の依存として同じ版が入っていたものを明示しただけ）。
- M02 で既存の算定を包むときは `model/legacy.py` の `to_legacy_input` を使い、`unavailable` の事実を
  既存コードの既定で進めたことを `StageResult.defaults_used` / `not_considered` に出す必要がある。

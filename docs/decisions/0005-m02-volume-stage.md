# 0005 M02 ボリュームの段と API の決め事

**状態：** 決定
**日付：** 2026-09-27
**決めた人：** Claude Code（M02 の指示の範囲内の実装上の選択）。ユーザーの確認待ちの点は末尾

## 背景

M02 で既存のボリューム算定を「案を受け取り StageResult を返す段」として包み、API から呼べるようにした。

## 決定

| 論点 | 決定 | 検討した選択肢 | 理由 |
|---|---|---|---|
| `solver.py` と `solver/` の名前の衝突 | `solver.py` を `solver/__init__.py` へ移した（中身は同じ）。`from solver import solve` はそのまま使える | 新しい段を `stages/` など別名の場所に置く | architecture.md §3 の目標構成（`solver/volume/`）どおりにするため。移動は「必要になったマイルストーンで行う」約束で、M02 で必要になった。中身が同じことはテストで照合する |
| API をどこで出すか | 別のアプリ `api/app.py` にし、127.0.0.1:8791 だけで待ち受ける。公開中の `web/app.py` には載せない | 既存の `web/app.py` に載せる | M02 の指示は「既存のサーバーがあれば使う」と「localhost のみ・認証なし」の両方を求める。既存のサーバーは Railway で公開されており、認証のない案の保存 API を載せると外から誰でも書き込める。安全側を採った |
| `solver_version` | `0.1.0+law.<constants.py の SHA-256 先頭12桁>`。版は `solver/volume/stage.py` の `SOLVER_PACKAGE_VERSION` | 全ソースのハッシュ | architecture.md 5章のとおり。法規定数ファイルの読み込みは api 側で行い、solver は入出力を持たない |
| 段の input_hash | `{"stage": "volume", "inputs": {敷地事実の値, 計画条件の値}, "upstream": {}}` の SHA-256 | 案の input_hash をそのまま使う | 後の段（上流の input_hash を含める）と同じ形にそろえる |
| 天空率 | ボリュームの段で毎回算定する（既存の `skyfactor.evaluate` の既定。通る案の探索を含む） | 別の段にする | M02 の指示が volume の結果に `sky_factor` を含めるため。1案あたり 0.1〜0.8 秒かかる |
| 適用規定の構造化 | 既存の label ごとに `rule_id` を付けた対応表（`solver/volume/rules.py`）。`article`＝既存の basis、`summary`＝「label：value」。`effect_mm2` は既存の規定ごとの削減量から、規定に1対1で当たる行にだけ付ける（道路斜線は「勾配」の行、建蔽率は緩和があれば「緩和後の建蔽率」、なければ「指定建蔽率」） | effect を付けない | 既存の出力にある値だけを使い、新しい値は作らない |
| 注記の振り分け | 未考慮事項（未考慮・未適用・未検証を述べるもの）と伝達事項（`warnings`。算定の方法や既定値で試算したことを述べるもの）に分ける。すべての注記がちょうど1か所に入ることをテストで確かめる | 全部を未考慮事項にする | 「外壁後退と斜線は大きいほうを適用」などは未考慮ではなく方法の説明のため |
| `direction` | project_brief 5章に対応が書いてあるものだけ設定（容積率不算入・法56条4項・法52条9項＝`smaller_than_actual`、日影規制＝`larger_than_actual`）。他は `unknown` | 推測で埋める | M02 の指示どおり |
| `defaults_used` | 既定値の計画条件に加え、**既存コードが不明な敷地事実に黙って使う既定**（road_side・真北・角地・防火地域・日影規制の指定）のパスも入れる | 計画条件だけ | 決定 0003 が「unavailable の事実を既存コードの既定で進めたことを defaults_used / not_considered に出す必要がある」としていたため。未考慮事項には足していない（既存にない項目を足さない約束） |
| 保存先 | 環境変数 `VOLUME_CHECK_DB`、既定 `.data/schemes.sqlite3`（git に入れない） | — | 要求ごとに開いて閉じる（SQLite の接続はスレッドをまたげない） |

## 影響

- 算定結果は変わらない（回帰ケース 13 件すべてで、M00 の結果と相対誤差 1e-9 以内で一致）。
- Web 画面・DXF は変えていない。

## ユーザーの確認が必要な点（完了報告で提案）

1. 日影規制の未実装を、住居系の案では常に未考慮事項（`larger_than_actual`）として出すか。いまは日影規制の指定を
   入れた案でしか出ない（既存の注記がそうなっているため。M02 では足していない）。
2. 高度地区・地区計画が不明（unavailable）のとき、未考慮事項として出すか。
3. 到達しない既存の注記2つ（current_state 11.）を、算定の修正として別のマイルストーンで直すか。

→ 1〜3 はユーザーが推奨どおりに承認し、決定 0006 で実装した。

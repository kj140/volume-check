# 0002 M00 回帰テストの固定方法

**状態：** 決定
**日付：** 2026-09-16
**決めた人：** ユーザー（Claude Code の提案を採用）

## 背景

M00 で現状の出力を回帰テストとして固定するにあたり、本体コードに手を入れずに
固定できない点が 3 つあった。

## 決定

| 論点 | 決定 | 検討した選択肢 | 理由 |
|---|---|---|---|
| DXF の表題欄「作成日時」が実行時刻で毎回変わる | テスト側で「作成日時」の値だけを比較から外す（`tests/regression/regress.py`） | drawer.py に日時を外から渡す口を足す | M00 は本体コードに手を入れない。ほかの図形・文字はすべて比較対象に残る |
| 外部 API（不動産情報ライブラリ）の応答を記録したいが API キーがない | 応答の形に合わせた**模擬データ**を `tests/fixtures/` に置き、ネットワークなしで通ることだけを確かめる。実応答はキーが使えるときに差し替える | キーを渡して実応答を記録する／M00 では fixtures を作らない | 回帰ケースの算定は API を使わない。キーがなくても「外に出ない」ことは担保できる |
| 既存の手計算ケース（`tests/test_solver.py`）の扱い | `tests/cases/` に写しを作る（calc.md ＋ expected.json ＋ input.json）。元のテストは残す | 場所の記録だけにする | 計算過程を文書として読める形にしておく。既存テストを壊さない |

## 影響

- 結果の数値には影響しない（本体コードは無変更）。
- `tests/fixtures/` の模擬応答を実応答に差し替えるときは、`tests/regression/zoning_lookup_offline/result.json`
  が変わる。M00 の記録の更新にあたるので、ユーザーの確認を得てから `record.py --force` で行う。
